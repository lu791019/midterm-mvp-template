## Part 2：上午專題報告指引

### 報告目的

讓講師和其他組了解你們的期末專題方向，及早發現問題、給予回饋。

### 報告格式

**不限格式**——投影片、HackMD、Notion、手繪白板都行。重點是內容清楚。

### 報告內容

分成**核心（必備）**和**延伸（加分）**兩部分：

---

#### 🔴 核心（必備）— 1~5 項

| # | 項目 | 說明 | 提示 |
|---|------|------|------|
| 1 | **製作動機 & 業務問題** | 要解決什麼問題？為什麼重要？ | 用一句話講清楚：「我們要幫 _____ 解決 _____ 的問題」 |
| 2 | **至少一項資料來源確認能取得** | 不是「打算用」，是「已經確認拿得到」 | 如果是 API，已經拿到 Key 或測過；如果是 CSV，已經下載看過 |
| 3 | **資料取得方式** | 怎麼拿到這份資料？ | Kaggle 下載 / 政府 Open Data / 爬蟲 / API / 公司內部？ |
| 4 | **資料欄位和格式** | 有哪些欄位？什麼型別？大概幾筆？ | 至少列出 5-10 個關鍵欄位，標出型別（數字/文字/日期） |
| 5 | **預期產出** | 最終要交付什麼？ | 例：Dashboard / API / 報告 / 預測模型。具體到「誰用、看什麼」 |

> 💡 **先把 1~5 準備好就夠了。** 如果時間不夠，6~8 可以在報告後的討論環節補充。

---

#### 🟡 延伸（加分）— 6~8 項

| # | 項目 | 說明 | 提示 |
|---|------|------|------|
| 6 | **初步技術堆疊** | 會用到哪些工具/技術？ | 列出來：pandas / SQLite / Airflow / Docker / BigQuery / LLM 等，標出「已學」vs「待學」 |
| 7 | **流程圖或 Pipeline 規劃** | 資料從進來到產出的路徑 | 不用精美，方塊 + 箭頭就夠。重點是看得出 input → 處理 → output |
| 8 | **預期風險 & 每週進度** | 什麼可能出問題？每週做什麼？ | 列 2-3 個風險 + 初步的週計畫（到期末） |

---

## ❓ 常見問題

**Q：不會 Python 怎麼辦？**
A：Notebook 有步驟提示和參考程式碼，也可以用 ChatGPT 幫忙。

**Q：沒有 OpenAI API Key 怎麼辦？**
A：LLM 分析有 fallback 規則版，不需要 API Key 也能完成。

**Q：專題報告準備不完怎麼辦？**
A：先準備 1~5 就好，6~8 可以討論時補充。重點是把方向講清楚。
